# 鲁香居 LUXIANGJU — 山东菜餐馆首页

一个零依赖、无需构建的单页鲁菜餐馆官网,直接双击 `index.html` 就能看。
品牌、菜品、门店信息均为虚构演示内容。

主打的 13 道菜全部配有独立插画:**九转大肠、葱烧海参、糖醋黄河鲤鱼、爆炒腰花、把子肉、四喜丸子、德州扒鸡、油焖大虾、奶汤蒲菜、五香熏鱼、鲁味酱牛肉、山东大煎饼、拔丝山药**。

## 视觉基调:宣纸 · 青瓷

浅色、通透、克制的一版设计。底色是温润的米白宣纸(不是纯白),强调色是青瓷绿,暖色用陶土橘,
正文用深绿灰而不是纯黑 —— 整体偏"顺眼舒服",避免刺眼。

三个约束是量化过的,不是凭感觉:

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 平均亮度 | **0.881** | 0=全黑,1=全白。浅色但不发白 |
| 过曝像素占比 | **13.1%** | 亮度 > 0.92 的部分,压到很低 |
| 深色像素占比 | **0.4%** | 亮度 < 0.30 的部分,基本没有重色块 |
| 平均彩度 | 0.085 | 比初版 0.066 更饱和,不发灰 |

配色变量集中在 `assets/css/style.css` 顶部的 `:root`:

```
--paper     #f0eade   宣纸底(页面背景)
--surface   #faf7f0   卡片面
--ink       #333a32   正文(深绿灰)
--celadon   #6e8f7a   青瓷绿,主强调
--clay      #b8825c   陶土橘,价格与暖色点缀
```

**插画也跟着换了底**:18 张菜品/环境图原本是深色木桌背景,直接放到浅色页面上会很割裂,
所以 `tools/build-art.mjs` 里的背景、器皿、光影、蒸汽全部改成了浅色版本,重新生成。
盘子保持明亮、载体压深一档,靠这个明度差把层次做出来。

## 怎么打开

直接双击 `index.html`;或者在本目录起一个本地服务:

```bash
python -m http.server 8000     # 然后访问 http://localhost:8000
```

## 页面区块

1. **首屏** — 主标题「食不厌精 / 脍不厌细」、双 CTA、三项经营数据(滚动到视口时递增)、葱烧海参主视觉与旋转印章
2. **滚动条幅** — 循环滚动的品牌主张
3. **关于鲁香居** — 图文不对称拼贴、三个卖点、28 年徽章
4. **招牌菜单** — 13 道菜配插画,支持按凉菜 / 热菜 / 海鲜河鲜 / 汤羹 / 主食 / 甜品筛选;**点卡片任意位置弹出详情**,看主料与配菜
5. **灶上功夫** — 吊、爆、扒、烧四张卡片,讲鲁菜的技法
6. **店内环境** — 明档厨房 / 堂食大间 / 老宅天井 / 茶席,四格无缝拼图
7. **食客说** — 自动轮播评价,支持圆点、箭头、键盘方向键与触屏滑动
8. **在线订座** — 表单校验(称呼 / 手机号 / 日期 / 时段 / 人数 / 同意条款)与提交反馈
9. **页脚** — 导航、联系方式、营业时间

## 关于菜品图片

本次环境里 **AI 生图不可用**(内置 `image_gen` 未挂载,`OPENAI_API_KEY` 未设置),
外部图库的检索接口也不通,所以菜品图走的是**手工绘制的矢量插画**路线:

- 全部 18 张菜品/场景图由 `tools/build-art.mjs` 生成,统一的光影、器皿、蒸汽脚手架,成套一致
- 每道菜的食材造型单独手写:九转大肠的环、糖醋鲤鱼的花刀、油焖大虾的风车摆盘……
- 矢量图,任意放大不糊,单张 6–19 KB,离线可用,**无任何版权风险**

### 重新生成或微调

```bash
node tools/build-art.mjs
```

生成后打开 `tools/_contact-sheet.html` 可以一次看全 18 张图。
改配色就改对应菜品的 `<linearGradient>`;改摆盘就改 `art` 里那组坐标。

### 想换成真实照片

图片已经是标准 `<img>` 引用,把 `assets/img/` 里的文件替换掉即可,尺寸比例保持 **4:3**(如 1200×900)。
如果换了文件名,同步改 `index.html` 里的 `src`。

想要 AI 生成的照片,可以让 `OPENAI_API_KEY` 就位后走 imagegen 技能的 CLI 兜底方案,或直接把成片丢进 `assets/img/`。

### 已抓好的真实照片候选

`assets/img/candidates/` 下有 13 道菜各 3–6 张真实照片候选。抓取用了两条链路:

1. **图片搜索** —— 走 Bing 图搜,按标题是否含菜名关键词打分,过滤图库水印站
2. **菜谱页成品图** —— 用网页搜索找菜谱页,**校验页面标题确实包含菜名**后才取正文里的成品图,比图搜可靠

```bash
node tools/fetch-photos.mjs --dry   # 只看候选标题和来源,不下载
node tools/fetch-photos.mjs         # 下载候选并刷新选择页
LICENSE_ONLY=1 node tools/fetch-photos.mjs   # 只取"可自由使用"许可的结果
```

打开 `tools/_photo-picker.html`,每道菜点一张选中,底部会生成一份清单,粘回对话即可接进页面。
选择页会给每组候选打可信度标记:绿色表示标题里命中了菜名,红色警告表示这组基本是搜歪的。

**两个注意点**

1. 候选来自公开网页(新浪、美食天下、下厨房等),版权归原作者;做演示可以,正式商用请换成自己拍的照片或图库授权图。
2. 搜索相关性并不稳定。**9 道**结果可用:九转大肠、糖醋黄河鲤鱼、爆炒腰花、德州扒鸡、把子肉、油焖大虾、奶汤蒲菜、五香熏鱼、山东大煎饼。
   **4 道拿不到**:葱烧海参、四喜丸子、鲁味酱牛肉、拔丝山药 —— 实测会被 Bing 返回大葱、演员写真、阅兵老照片、拔丝地瓜这类完全无关的图。

### 为什么只有 9 道

这不是查询词没写好,而是图源本身不可靠:

| 图源 | 结果 |
| --- | --- |
| 百度图库 | `{"antiFlag":1,"message":"Forbid spider access"}` 明确拒绝 |
| 搜狗图库 | `{"status":1,"info":"forbid"}` 明确拒绝 |
| 360 图库 | 连接超时 |
| Wikimedia / Openverse | 网络不通 |
| Bing 图搜 | 能通,但对部分菜名会返回**完全无关的结果**(四喜丸子→演员写真、酱牛肉→阅兵照片),且每次运行结果都在变,像是被动降级 |

另外 `Bing 网页搜索 → 菜谱页 → 取成品图` 这条链路是通的,页面标题能确认菜名,但 Bing 对 `site:` 查询返回的链接很少,
命中率不稳定,只补上了少数几张。所以这 4 道菜建议自己拍,或者走下面 AI 生成那条路。

### 用 AI 生成照片(推荐)

要真实且准确、又没有版权问题的做法是 AI 生成,但需要本机先配好密钥:

1. 到 https://platform.openai.com/api-keys 建一个 API Key
2. 设为系统环境变量 `OPENAI_API_KEY`
3. 回来告诉我一声,我按 imagegen 技能的 CLI 流程生成 13 张 4:3 的菜品照片

注意:不要把完整密钥贴到对话里,设成本机环境变量就行。

## 点开一道菜看什么

鼠标悬停卡片时右下角出现「查看主料 · 配菜」提示(触屏设备常驻显示),点击卡片任意位置弹出详情:

- **主料**:单独成行、金色高亮标签,一眼看到这道菜的主角是什么、多少克
- **配菜**:普通标签平铺,分清哪些是辅料
- 再往下是**调料 / 技法 / 口味 / 分量**,以及一条**实用提示**(比如「九转大肠现做约 25 分钟,建议订座时预留」)
- 底部可**上一道 / 下一道**翻看(← → 方向键也行),或者点「订座时预留这道菜」——会自动把菜名写进订座表单的备注栏,再跳到订座区

筛选切到「凉菜」再点菜,翻页只在筛选结果里循环。键盘 `Tab` 聚焦卡片、`Enter` 打开,`Esc` 关闭后焦点会回到原来那张卡。

菜品详情的数据就写在每张卡片里的 `.dish__detail` 区块,和卡片放在一起,改文案不用碰 JS。

## 交互与无障碍

- 页头随滚动切换为毛玻璃实底,顶部有阅读进度条,右下角回到顶部按钮
- 移动端汉堡抽屉导航,打开时锁定页面滚动,`Esc` 可关闭
- 全站键盘可达:跳转链接、可见焦点环、`aria-*` 状态同步
- 进场动画、数字滚动、轮播自动播放在 `prefers-reduced-motion: reduce` 下自动关闭
- 关闭 JavaScript 时内容依旧完整可见(`<noscript>` + IntersectionObserver 兜底)
- 表单错误有文字提示且聚焦到第一个出错字段,手机号 / 日期做真实校验

## 后续可接的真实能力

- **地图**:在订座区块插入高德 / 百度地图的 iframe 或 JS API

## 发布到 GitHub Pages

仓库已经初始化好(分支 `main`,含 `.nojekyll` 与 `.gitignore`),推上去之后在仓库
**Settings → Pages → Source** 选 `Deploy from a branch`、分支选 `main`、目录选 `/ (root)`,
大约一分钟后就能通过下面这个地址访问:

```
https://<你的用户名>.github.io/<仓库名>/
```

因为是纯静态站点,不需要任何构建步骤,GitHub 会直接托管 `index.html`。

以后改完内容,推送三步:

```bash
git add -A
git commit -m "更新内容"
git push
```

> 注意:`assets/img/candidates/`(抓取的照片候选,约 17MB)已在 `.gitignore` 里排除,
> 不会上传。确定不用可以直接删掉这个目录。
